# ACT SDLC Workflows

natserract के डेवलपमेंट वर्कफ़्लो के लिए एक Claude Code प्लगइन। काम एक Linear इश्यू (issue) के रूप में शुरू होता है, और act-sdlc इसे आइडिया से रिलीज़ तक ले जाने में आपकी मदद करता है:

```
 Linear इश्यू ──► /plan ──► /to-spec ──► Linear में रिव्यू ──► /start ──► /verify ──► रिलीज़
                 ट्रायज     RFC            (टीम अप्रूव             एक बार में    टेस्ट, डिज़ाइन,
                 और स्प्लिट  लिखें          करती है)                एक टास्क     और सिक्योरिटी
                                                                 बनाएं         चेक करें
```

हर इश्यू के लिए Linear में एक **RFC** (एक प्लान डॉक्यूमेंट) मिलता है। टीम वहां इसका रिव्यू करती है और इसे अप्रूव करती है, और Claude उस काम को बनाने (build) और चेक करने के लिए इसका पालन करता है।

## क्विक स्टार्ट (Quick start)

**1. इंस्टॉल करें** (सिर्फ एक बार):

```bash
claude plugin marketplace add natserract/ai
claude plugin install act-sdlc@actual
```

**2. अपनी मशीन सेटअप करें** (सिर्फ एक बार), Claude Code के अंदर:

```
/act-sdlc:init      # आपका वर्कस्पेस ~/.act/ बनाता है
/act-sdlc:setup     # आपकी ट्रांसलेशन API की (key) जोड़ता है (वैकल्पिक)
```

**3. किसी इश्यू पर काम करें,** उदाहरण के लिए ACT-95:

| स्टेप | कमांड चलाएं | क्या होता है |
| :- | :- | :- |
| 1. प्लान (Plan) | `/act-sdlc:plan ACT-95` | चेक करता है कि क्या इश्यू तैयार है, लेबल्स जोड़ता है, और अगर यह बहुत बड़ा है तो इसे सब-इश्यू में बांट देता है |
| 2. प्लान लिखें | `/act-sdlc:to-spec ACT-95` | RFC लिखता है और इसे Linear में इश्यू पर पोस्ट करता है |
| 3. अप्रूव (Approve) | *(Linear में)* | टीम RFC का रिव्यू करती है, फिर इश्यू को **In Progress** में ले जाती है |
| 4. बनाएं (Build) | `/act-sdlc:start ACT-95` | मौजूदा रिपॉजिटरी (repo) के लिए अगला टास्क करता है, उसे चेक करता है, और RFC में उस पर टिक लगाता है। अगले टास्क के लिए इसे फिर से चलाएं |
| 5. चेक करें (Verify)| `/act-sdlc:verify ACT-95` | टेस्ट, डिज़ाइन और सिक्योरिटी चेक करता है, और RFC में पास या फेल रिकॉर्ड करता है |
| 6. रिलीज़ (Release)| *(Linear में)* | इसे शिप करें, फिर इश्यू को **Done/Released** में ले जाएं |

समझ नहीं आ रहा क्या करें? सभी कमांड और अपने सेटअप की जांच के लिए `/act-sdlc:help` चलाएं, या यह जानने के लिए कि इश्यू अभी कहां है और आगे क्या करना है, `/act-sdlc:status ACT-95` चलाएं।

## कमांड्स (Commands)

### रोज़मर्रा के काम (Day to day)

| कमांड | इसका उपयोग करें |
| :- | :- |
| `/act-sdlc:plan <issue>` | इश्यू को ट्रायज करने के लिए, और बड़े इश्यू को छोटे सब-इश्यू में बांटने के लिए |
| `/act-sdlc:to-spec <issue>` | इश्यू का RFC लिखने और उसे Linear पर पोस्ट करने के लिए |
| `/act-sdlc:start <issue>` | मौजूदा रिपॉजिटरी में अगला RFC टास्क बनाने के लिए |
| `/act-sdlc:verify <issue>` | रिलीज़ से पहले मौजूदा रिपॉजिटरी में पूरे हो चुके काम को चेक करने के लिए |
| `/act-sdlc:status <issue>` | यह देखने के लिए कि इश्यू की स्थिति क्या है और आगे क्या करना है |
| `/act-sdlc:review <PR link or issue>` | अपने किसी टीममेट के पुल रिक्वेस्ट (PR) का रिव्यू करने के लिए |

### पढ़ने के लिए (Reading)

| कमांड | इसका उपयोग करें |
| :- | :- |
| `/act-sdlc:open <issue>` | अपनी भाषा में RFC खोलने के लिए (अंग्रेज़ी के लिए `--en`, Linear में खोलने के लिए `--linear`) |
| `/act-sdlc:translate-issue <issue>` | किसी Linear इश्यू को अपनी भाषा में ट्रांसलेट करने के लिए |

### सेटअप (Setup)

| कमांड | इसका उपयोग करें |
| :- | :- |
| `/act-sdlc:init` | अपना वर्कस्पेस `~/.act/` बनाने के लिए (प्रति मशीन एक बार) |
| `/act-sdlc:setup` | अपनी ट्रांसलेशन API की (key) जोड़ने या चेक करने के लिए |
| `/act-sdlc:config` | अपनी सेटिंग्स देखने या बदलने के लिए |
| `/act-sdlc:help` | सभी कमांड देखने, अपना सेटअप जांचने, और जिस रिपॉज़िटरी में आप हैं उसके लिए सुझाव पाने के लिए। `/act-sdlc:help start` एक कमांड को समझाता है |

`<issue>` एक इश्यू की (key) है जैसे `ACT-95`, या एक Linear इश्यू का URL.

<summary><b>हर कमांड के विकल्प (Options)</b></summary>

| कमांड | विकल्प (Options) |
| :- | :- |
| `plan` | `--no-split`: सब-इश्यू बनाए बिना प्रस्तावित स्प्लिट (बंटवारा) दिखाएं |
| `to-spec` | `--no-publish`: RFC को पोस्ट करने के बजाय अपनी मशीन पर ही रखें |
| `start` | `--task 2.2`: कोई विशिष्ट टास्क। `--group 3`: पूरा टास्क ग्रुप। `--all`: हर ओपन (खुला) टास्क। `--force`: RFC अप्रूव होने से पहले शुरू करें |
| `verify` | `--deep`: अधिक गहन (deep) सिक्योरिटी रिव्यू। `--base <branch>`: किसी अन्य ब्रांच से तुलना करें |
| `review` | `--deep`: अधिक गहन सिक्योरिटी रिव्यू। `--no-comment`: PR पर पोस्ट न करें |
| `open` | `--en`: अंग्रेज़ी RFC। `--linear`: इसे Linear में खोलें। `--print`: इसे चैट में दिखाएं |
| `translate-issue` | `--lang in`: कोई अन्य भाषा। `--force`: फिर से ट्रांसलेट करें। `--summary`: केवल सारांश दिखाएं |

</details>

## हर स्टेप क्या चेक करता है

- **`/plan`:** क्या इश्यू स्पष्ट है, और क्या इसमें एक्सेप्टेंस क्राइटेरिया (acceptance criteria) हैं? क्या यह एक RFC के लिए काफी छोटा है? अगर यह बहुत बड़ा है, तो इसे **decision** टिकट (जिन सवालों के जवाब पहले देने हैं) और **work** टिकट में बांट दिया जाता है, और उनके बीच एक क्रम तय किया जाता है।
- **`/to-spec`:** RFC के चार भाग होते हैं:
  1. **Proposal (प्रस्ताव):** काम की आवश्यकता क्यों है।
  2. **Requirements (ज़रूरतें):** क्या सच होना चाहिए, टेस्ट करने योग्य परिदृश्यों (scenarios) के रूप में।
  3. **Design (डिज़ाइन):** यह कैसे काम करता है, जिसमें एक [Call Graph](docs/call-graph.md) डायग्राम और कोड के हर हिस्से के बारे में **किससे पूछना है**, यह शामिल है।
  4. **Tasks (टास्क):** एक चेकलिस्ट, जहां हर टास्क को उसके रिपॉजिटरी के साथ टैग किया गया है।
- **`/start`:** RFC के डिज़ाइन का पालन करता है, हर टास्क का अपना चेक चलाता है, और उसके बाद ही टास्क पर टिक लगाता है।
- **`/verify`:** हर परिदृश्य (scenario) का एक पासिंग टेस्ट होता है, कोड डिज़ाइन से मेल खाता है, एक कोड रिव्यू होता है, और OWASP Top 10 पर आधारित एक [सिक्योरिटी रिव्यू](docs/security-review.md) होता है, जो ऑथेंटिकेशन, पेमेंट्स, और पर्सनल डेटा जैसे संवेदनशील क्षेत्रों के लिए अधिक गहराई से चेक करता है।
- **`/review`:** चेकआउट किए बिना एक पुल रिक्वेस्ट (PR) पर यही चेक करता है। यह PR पर रिव्यू पोस्ट कर सकता है, और आपके द्वारा चुनी गई कमियों/सुझावों को नए Linear इश्यू में बदल सकता है।

## act-sdlc क्या बदलता है, और क्या नहीं

| कहां | act-sdlc यह कर सकता है | यह कभी नहीं करता |
| :- | :- | :- |
| **Linear** | RFC और एक कमेंट पोस्ट करना (`/to-spec`); लेबल्स जोड़ना और सब-इश्यू बनाना (`/plan`); टास्क पर टिक लगाना (`/start`); RFC में verify रिज़ल्ट रिकॉर्ड करना (`/verify`); आपके द्वारा चुने गए इश्यू बनाना (`/review`) | किसी इश्यू का स्टेटस, असाइनी (assignee), टाइटल या डिस्क्रिप्शन बदलना, या लेबल्स हटाना |
| **GitHub** | PR पर कमेंट रिव्यू पोस्ट करना, जब आप चाहें (`/review`) | अप्रूव (Approve) करना या बदलावों की मांग (request changes) करना |
| **आपका कोड** | बनाते समय (build) फाइल्स एडिट करना (`/start`) और टेस्ट्स जोड़ना (`/verify`) | ब्रांच बनाना या स्विच करना, कमिट (commit) या पुश (push) करना। Git आपका काम है |
| **आपकी मशीन** | ड्राफ्ट्स और ट्रांसलेशन्स को `~/.act/` में रखना, और सेटिंग्स को `~/.config/act-sdlc/` में रखना | आपके ऐप रिपॉजिटरी में फाइल्स जोड़ना |

इश्यू के स्टेटस को बदलना, काम सौंपना, और PR को अप्रूव करना लोगों का काम है।

## सेटिंग्स (Settings)

सेटिंग्स व्यक्तिगत होती हैं। उन्हें `/act-sdlc:config` के साथ बदलें:

```
/act-sdlc:config show                          # हर सेटिंग देखें
/act-sdlc:config set translate.language in     # हिंदी में ट्रांसलेट करें
/act-sdlc:config set rfc.publish false         # RFC को अपनी मशीन पर रखें
```

| सेटिंग | डिफ़ॉल्ट | यह क्या करता है |
| :- | :- | :- |
| `translate.language` | `id` | आपकी भाषा, एक कंट्री कोड के रूप में: `id` इन्डोनेशियाई, `in` हिंदी, `jp` जापानी, और [अन्य](docs/translation.md#choose-a-language) |
| `translate.provider` | `gemini` | कौन सा AI ट्रांसलेट करता है: `gemini`, `claude`, `openai`, या `openrouter` |
| `translate.model` | खाली (empty) | एक विशिष्ट मॉडल। `openai` और `openrouter` के लिए आवश्यक |
| `translate.auto` | `false` | जब आप Linear इश्यू का लिंक पेस्ट करें तो अपने आप ट्रांसलेट करें |
| `rfc.publish` | `true` | Linear में RFC पोस्ट करें |
| `plan.autoSplit` | `true` | बड़े इश्यू को अपने आप सब-इश्यू में बांट दें |
| `phases.lightLabels` | `Small Size` | छोटे इश्यू के लेबल्स जिन्हें छोटा RFC मिलता है |
| `phases.callGraph` | `true` | हर पूरे RFC में एक Call Graph अनिवार्य करें |
| `start.skills` | खाली (empty) | हर टास्क के लिए चलाए जाने वाले अतिरिक्त स्किल्स, उदा. `code-review` |

अधिक जानकारी: [docs/configuration.md](docs/configuration.md).

## इंस्टॉल विकल्प (Install options)

**ज़रूरतें (Requirements):**
- Claude Code;
- Node.js 20.19 या बाद का वर्ज़न;
- Claude से कनेक्टेड Linear, आपकी claude.ai कनेक्टर सेटिंग्स या `/mcp` के माध्यम से;
- केवल `/review` के लिए, लॉग इन किया हुआ GitHub CLI (`gh`).

**पूरी टीम के लिए:** इसे प्रोजेक्ट की `.claude/settings.json` में कमिट करें, ताकि जो कोई भी प्रोजेक्ट खोले उसे प्लगइन ऑफर किया जाए:

```json
{
  "extraKnownMarketplaces": {
    "actual": { "source": { "source": "github", "repo": "natserract/ai" } }
  },
  "enabledPlugins": {
    "act-sdlc@actual": true
  }
}
```

**लोकल क्लोन से** (अपडेट `git pull` के साथ आते हैं):

```bash
git clone https://github.com/natserract/ai.git
cd ai
claude plugin marketplace add ./
claude plugin install act-sdlc@actual
```

**प्लगइन पर ही काम करने के लिए:**

```bash
claude --plugin-dir ./workflows/act-sdlc
```

प्लगइन का सोर्स [`workflows/act-sdlc`](https://github.com/natserract/ai/tree/main/workflows/act-sdlc) में है। `actual` मार्केटप्लेस रिपॉजिटरी रूट पर `.claude-plugin/marketplace.json` में परिभाषित है।
